## 程序输出与复现

- 最终工作簿：`outputs/initial20-20261010-final/岗位信息汇总.xlsx`，按用户模板十一字段输出，另附二十行企业采集情况和原模板枚举/说明。
- 原始数据、待补全原因和报告：同目录 `jobs.json`、`review.json`、`report.json`。
- 新企业独立采集：`outputs/twenty-company-validation/<来源ID>/`，每家含来源快照、证据和报告。
- 明确选择的二十家快照：`outputs/initial20-inputs.json`。合并可用 `uv run job-crawler bundle --inputs-file outputs/initial20-inputs.json --output outputs/another-export`，不会重抓招聘网站。
- 常规重新采集：`uv run job-crawler run --output outputs/new-run`；默认启用名单已扩展至二十家。只采一家时增加 `--source COM0056` 等参数。

上述 outputs 均为本机产物，按规范不进入 Git；代码、绑定、最小公开回放样本和文档进入 Git。

## 接入中确认的问题

1. 保利原分享筛选仅 3 条，取消局部筛选后校招目录为 213 条；神州数码原链接限定城市/分类为 14 条，完整目录为 97 条。适配器拒绝带局部分类/地区/关键词筛选的请求冒充全量。
2. 北森前端异步加载中可能被 Crawl4AI 的空壳启发式提前判失败。仅当本轮目标页面和声明的业务接口成功返回 JSON 后恢复；真正 403、验证码及无业务数据的页面不放行。监听期间不重复提取未完成的空壳。
3. 详情日期 `0001-01-01` 是未设置哨兵，不当作已截止；实际没有发布日期的记录在日期窗口模式中待核验，不用 ChangeDate 替代。
4. 初始页面暂时显示零或空白不证明目录为零。长沙银行、东山精密等待实际列表后分别取得 47、15 条。备用金风科技另采得 69 条并保留在本地，未加入本次二十家绑定或汇总。
5. Moka、飞书及北森旧版等调查产物保留为接入证据，本轮没有宣称这些候选已全部支持。

分类树按此前约定独立配置，尚未提供真实父子关系，故当前 4,611 条全部进入待补全报告，严格 `jobs.xlsx` 为零行。部分来源学历只写在正文或地点为多城市，也需后续规范化。这与采集覆盖通过是两回事；信息汇总表可用于查看和补全，不能宣称整表可直接导入后台。
