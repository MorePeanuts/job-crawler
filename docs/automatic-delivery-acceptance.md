# 默认自动补全交付验收

对应 [SPEC-010](../specs/010-automatic-delivery.md)。本轮只运行模拟浏览器、模拟模型和离线回归；没有访问真实招聘网站或调用付费模型，也没有重新生成二十家企业的实时岗位表。

## 已交付行为

默认 `run` 在抓取并保存原始快照后自动筛选、规则规范化、批量分类/复核、必要学历辅助和校验导出。最终 `jobs.xlsx`、`岗位信息汇总.xlsx` 在同一输出根目录，不需要用户再运行 classify。原始 jobs.json/collections 与规范化 delivered.json 分离，字段来源和未解决项可复核。

默认模型开关已开启；分类、复核和学历请求共用 1000 次预算。分类批次、并发、缓存路径、复核及预算可配置。分类兼容已有缓存身份；成功复核缓存优先于重新尝试基础分类。学历使用独立内容缓存并在命中时核对引证；已被规则确认的学历不请求模型。

## 需求与测试对应

`tests/test_delivery.py` 通过真实 CLI/runner/北森适配器/SQLite/Excel 导出器，替换浏览器和模型网络 I/O，验证：

| 场景 | 验收结果 |
| --- | --- |
| 默认 all/day 单命令 | 自动分类、学历补全，严格表十二列，退出码 0 |
| 下一轮相同内容 | 分类和学历缓存均命中，模型调用从 2 次变为 0 次 |
| 缺 key | 保留原始岗位、信息表、错误报告，退出码 2 |
| 修复后 export | 自动补齐并出表，不创建第二个浏览器会话，保留原筛选时刻 |
| 总预算 1 次 | 分类成功后学历不再请求；分类非法引证也不会绕过预算重试 |
| 窗口外、日期待核验、字段已合法 | 不送模型，原合法分类保留 |
| 学历缓存变更 | 文本、模型、学历策略变更或损坏引证使缓存失效；有效缓存可无 key 复用 |
| 只有成功复核缓存 | 直接使用，不重试未缓存的基础分类 |
| 模型超时 | 已合法岗位继续进入严格表，其余待补全；报告不输出密钥 |
| 显式禁用模型 | 不调用模型，按原始/规则结果交付和报告 |

`uv sync --locked`、Ruff 格式/静态检查及 ty 均通过，**226 项测试通过**（含新增 13 项自动交付测试）。既有分类、日期、分页、详情复用、字段提取、导入校验测试继续通过。测试结果记录于本地 `outputs/automatic-delivery-verification/junit.xml`（不入库）。

## 限制

自动补全不等于所有岗位一定可直接导入。源站字段缺失、含糊学历/分类、非法地点格式、无法解析的日期仍需明确报告。模型有引证并通过结构校验，也不能代替业务语义抽样核验。API 服务的可用性和真实模型输出质量本轮未重新验证。定时调度仍由外部负责。
