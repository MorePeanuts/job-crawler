# 日期归档与清理验收（2026-10-14）

对应 SPEC-047。实现默认 CLI 日期交付、压缩归档、恢复、自动维护及显式开发目录兼容。没有重新访问招聘网站或调用 LLM；未合并 main。

## 本机历史迁移

程序压缩 275 个开发目录以及一份零散文件归档，共 276 份。每份压缩包创建后逐文件校验 SHA-256，确认原目录没有变化后登记索引，再删除未压缩副本。五个 QA 的 node_modules 符号链接仅删除链接，目标依赖未修改；链接原位置和目标记录在本机迁移报告中。

## 离线验收与限制

`tests/test_retention.py` 覆盖逐字节恢复、同名拒绝覆盖、历史日期、压缩校验失败保留原件、符号链接和路径穿越拒绝、归档损坏、原始证据删除后的每日详情复用、已引用/最新/固定归档保护、清理预览、缓存大小和年龄淘汰、缺失状态库停止清理、默认 CLI 交付与恢复后离线重导出。现有分页、字段及模型测试同时回归。最终 uv sync --locked、Ruff 格式/静态检查、ty 和 376 项 pytest 全部通过。

固定交付归档长期保存；非固定归档至少 30 天、每个来源和窗口的最新快照和活跃状态引用继续保护。LLM 缓存默认 90 天/2 GiB 上限。本次没有淘汰模型缓存。被保护数据不是硬磁盘配额，不能直接删除 .runtime 以替代维护命令。

增量身份仍包含代码摘要，代码升级可能按已有规则重新建立基线；本次只证明归档后的证据可读、同身份的缓存可复用，没有修改旧历史身份或绕过代码版本校验。restore 恢复原始快照，配置更改后的 export 仍可能按配置调用 LLM。

归档仅用于停止写入的目录；已有中断采集的工作目录仍保留，可在既有恢复期限内 --resume。锁防止归档/清理命令同时更新索引，实际采集进程不应与手动 archive 操作同一运行目录。文件校验能检测压缩期间的变更，但不替代停止写入的要求。
