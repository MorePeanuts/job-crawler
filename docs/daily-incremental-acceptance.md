# 每日详情请求优化验收

对应 [SPEC-009](../specs/009-daily-incremental.md)，目标版本 `v0.0.1-alpha.2`。本轮使用合成站点、已有真实字段回放及模拟浏览器编排测试，没有访问招聘网站、调用模型或重新生成 20 家真实岗位快照。

## 请求量对比

| 回放情景 | 优化前 | 优化后 | 正确性核验 |
| --- | --- | --- | --- |
| 1,000 岗位、每页 20 条，末页 20 条为当天岗位 | 50 列表 + 1,000 详情 | 50 列表 + 20 详情 | 选中岗位 ID 集合一致，980 条窗口跳过，完整目录核对通过 |
| 21 条无日期岗位，已有全量基线且次日列表未变 | 2 列表 + 21 详情 | 2 列表 + 0 详情 | 保留原正文/采集时间，不重新打开详情入口，基线岗位不作为新增 |
| 上述目录增加 1 条、已有 1 条列表变化 | 全部 22 条详情 | 只读新增及变化的 2 条详情 | 新增标为 first_discovered_without_publication；旧岗位不伪装为首次发现 |
| 中石油 1 篇公告展开 2 个岗位，次日列表未变 | 1 篇详情 | 0 篇详情 | 复用计数为 1 篇，输出仍保留 2 个岗位 |
| 强制 all 全量刷新 | 全部详情 | 全部详情 | 无跨轮缓存复用；建行既有过期跳过规则保留 |

第一项显式 API 请求从 1,050 降至 70，减少约 93.3%。这些数字不包含浏览器入口加载和静态资源，也不是对线上网站节省比例或耗时的承诺。

## 验收覆盖

- `tests/test_incremental.py`：日期精度、24 小时边界、未知/无效/未来日期、冷启动、热缓存、变化、缺失证据、缓存损坏、15 天刷新边界、重新出现、空目录、局部失败、身份隔离及四平台/北森回放。
- `tests/test_daily_runner.py`：全量基线 → 下一天新增，走真实 runner/SQLite/export；只读取新增详情，生成仅包含每日新增的十二列表，重导出保留筛选时刻。
- `tests/test_bundle.py`：每日简略记录不会因为汇总变为全量，拒绝混合窗口。
- `tests/test_classification.py`：all/day 快照均可离线命中分类缓存、复核并保持原窗口，无模型请求。
- 原有真实字段回放、来源覆盖、分类、学历、模板、网络错误与恢复测试继续通过。

## 使用限制

升级后应先运行一次 all 建立新版历史，并保留共用的状态数据库及证据目录。旧版记录不具备可信列表指纹，不直接用于跳过请求。只有通过覆盖核对的来源推进历史；某来源失败不会覆盖其旧基线。

没有发布日期的“新发现”仅说明首次观察时间，绝不补成发布时间。列表未变但详情变更，包括旧公告内部新增岗位，可能等到 15 天刷新或主动 all 才被发现。可靠旧发布日期可以直接排除；不会因为缓存到期而强制读取本来已不在每日窗口内的详情。日期缺失时不能提前终止分页。

本轮未实现定时调度、失败跨日自动补采、跨轮交付去重或任意网页自主导航。每次 run 同时输出严格导入表和含待补全记录的信息表，分类仍可用独立 classify 命令。模板校验未通过的岗位不会被强行放入严格表。
