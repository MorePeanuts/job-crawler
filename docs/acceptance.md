### SPEC-003 归因纠正与复验

此前直接将中石油、阿里归为“需要可访问环境”证据不足。对照原验证分支 `462513b` 的实现和同日上午成功证据后，分别复现：

- 中石油旧成功入口状态为 412；同环境重跑旧实现仍收到 `listN` HTTP 200。正式版新增的 HTTP >= 400 立即失败导致回归。已改为仅在本轮目标页和指定业务接口成功返回 JSON 时继续，保留导航警告和完整依据。
- 阿里旧实现现在也在 60 秒导航处超时，且未发起岗位接口。请求追踪显示主程序 `g.alicdn.com/CPO-platform/recruit-portal/1.0.6/js/index.js` 尚未完成；90 秒独立下载只收到约 2.7 MB / 7.3 MB。放宽为 180 秒后首个页面约 91 秒完成，真实获得 469 条岗位，并核验 160 条阿里星子集。正式配置现将导航超时（180 秒）与 API 超时（60 秒）分开。

诊断证据在 `outputs/entry-regression/`，长等待对照采集在 `outputs/production-entry-fix-alibaba/`。测试新增本轮/旧响应隔离、完整接口集合、JSON/同源/目标地址检查、403 不放行、恢复警告、监听器去重、独立超时；恢复本身不改变覆盖率和导入规则。

中石油修复后运行 `uv run job-crawler run --source COM0002 --output outputs/production-entry-fix-cnpc-v2`，完整获取 132 篇公告、1,190 条岗位。`report.json` 中 `coverage=complete`、`issues=[]`，`warnings` 保留入口 412 的恢复依据。修复过程首轮因就绪前缀遗漏 `/web` 仍失败，保留在 `outputs/production-entry-fix-cnpc/`，不作为通过依据。

阿里正式配置复验命令：`uv run job-crawler run --source COM0015 --output outputs/production-entry-fix-alibaba-final`。2026-10-10 14:40:18 至 14:42:41 +08:00，导航 180 秒/API 60 秒，取得 469 条岗位、160 条阿里星子集，`coverage=complete`、`issues=[]`。没有注入历史结果或绕过认证。

两站原始数据和模板分别由程序保存为各目录的 `jobs.json`、`jobs.xlsx`，待补全字段在 `review.json`。即使采集覆盖 complete，缺少导入字段时整体状态仍为 partial、退出码仍为 2，不能据此认定采集失败。

## 当前限制

1. 网站状态和网络速度随时间变化；本次真实验收只证明声明目录的当轮覆盖，不承诺随时可达。页面超时需结合当前业务接口和资源证据诊断，不能直接归因于站点封禁。
2. 分类树按用户要求独立配置，尚未获得真实后台父子关系。地点与非标准学历也需明确映射，不进行猜测。没有连接用户导入后台，未执行真实整表导入。
3. 本轮只实现公开校招目录，不含登录会话导入、验证码处理、扫描附件 OCR、其他 224 个链接适配、定时调度或分布式执行。
4. 恢复重取目录并复用同运行的成功详情，保留采集时间；招聘网站不是事务快照，不承诺跨分钟绝对一致。原运行超过恢复时限或代码/配置变化时必须新建任务。

以上限制均在 README、配置及运行状态中可见，不以离线测试通过替代真实访问结果。
