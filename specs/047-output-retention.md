# SPEC-047 日期归档与运行产物清理

状态：开发中。

## 目标与非目标

用户只需在 outputs/YYYY-MM-DD 查看最终表格；中间文件压缩保存于 .runtime，减少开发磁盘占用，保留每日详情复用、模型缓存和离线重导出能力。不改变筛选、模板、岗位内容、采集时间或增量身份，不自动访问网站/调用模型，不合并不同筛选时刻的 day 窗口。

## 输入输出与规则

- 默认 CLI run 使用 .runtime/runs/<唯一运行名> 工作目录；生成表格后发布至 outputs/实际启动日期/，文件名区分窗口与运行。同日运行不覆盖已有交付（不同 day 筛选时刻不混合）。显式 --output 仍为兼容的开发目录，可用 archive 命令发布归档。
- archive 接收已停止使用的运行目录，先创建 ZIP、逐文件校验，再登记原路径到归档的索引，最后删除未压缩文件。证据存在检查与读取支持已登记的 ZIP 路径；不改写 SQLite 历史、不删除状态、不将首次发现重置。
- ZIP 保留完整快照、报告及历史证据，原始 Excel 保存在归档内便于复核。输出目录仅发布汇总及严格导入表；记录日期、来源和原路径映射在后台索引中。历史发布日期来自 manifest.as_of，不能用清理日期冒充。
- restore 解压到新的空目录，拒绝路径穿越、链接和覆盖；恢复后可以 export/bundle。原证据引用仍可通过归档索引解析。
- maintenance 默认预览，--apply 执行：未固定归档保留至少 30 天（从归档时刻算）；每个来源/窗口的最新快照始终保留，重要交付可用 --pin 固定保留。包含仍被 source_history 引用的证据归档不清除。原始 SQLite 永不自动删除；默认 LLM 缓存保留 90 天且上限 2 GiB，超限先淘汰最旧文件（可能增加未来模型调用），可配置。每次默认 run 交付后执行维护。
- 旧开发目录先统一压缩，选定最终结果发布并固定；零散探测日志也归档，未知文件不静默丢弃。保留迁移清单、字节统计和哈希核验记录。未完成/运行中的目录禁止自动迁移，要求离线执行 archive。

## 失败行为

压缩/校验/发布失败保留原件；索引原子更新。路径已登记或发布目标冲突时拒绝覆盖；压缩后的证据缺失/损坏回退正常请求逻辑。默认采集失败未到导出阶段保留工作目录并显示恢复路径。清理遇到损坏索引/无法读取数据库须中止，不能将保护集合当空。无需直接删除全部 outputs 或 .runtime。

## 验收对应

tests/test_retention.py：压缩与恢复逐字节相同、越界/覆盖拒绝、压缩失败保留原件、历史日期/同日重名保护；每日详情在原证据删除后仍能复用；保护数据库引用归档；到期预览不删除、应用只删可淘汰数据；默认 CLI 使用日期交付目录，保留显式输出兼容。

真实迁移验收记录 docs/output-retention-acceptance.md；记录清理前后目录体积、发布清单及最终表格哈希，不将离线迁移描述为重新采集。
