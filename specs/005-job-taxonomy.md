# SPEC-005 岗位分类配置与历史数据补全

状态：已实现并完成真实数据验证。4,611 条记录中 4,599 条完成分类，12 条有明确待核验原因；不声称这些混合岗位/非岗位公告可以唯一分类。见 `docs/taxonomy-acceptance.md`。

## 目标与输入输出

以用户提供的 `job-position.js` 为分类权威来源。只解析其中的数据常量，不执行 JavaScript。一级 name → groups[].name 为允许的父子路径；positions 保留为语义判断参考，不增加 Excel 列。生成独立可维护的分类资源，并同步默认 config.toml 的分类树；与原模板枚举核对，不凭独立枚举猜测父子关系。

对已保存二十家企业快照中的未排除岗位补充分类，再由程序导出原十一字段的岗位信息表。保留原始快照、来源采集时间、过滤理由及覆盖统计；本轮不是重新采集。已截止岗位不为凑齐企业行数生成占位记录。

## 行为与失败

新增离线 classify 命令：读取快照、按显式参考时刻筛选，使用 deepseek-flash 根据名称、来源分类、职责、要求判断最合适的合法路径；网页内容仅作数据。模糊或跨职能且不能判断的记录保留未分类和原因，禁止强塞兜底类。明确培训生项目可归管培生，不能把普通校招统称管培生。

批量推理限制并发、每批数量、超时、重试和总调用量。响应逐条核对 ID、完整性、父子关系、原文引证；无效响应重试并保留诊断。分类判断须标记为模型推断，而非源站事实。缓存包含输入内容、模型配置、分类树和提示版本的指纹；成功项立即保存，后续运行可复用，修改任何判断输入必须失效。未分类结果不冒充成功。输出单独的分类审计报告与增强快照，后续 bundle/export 可直接复用分类而不用再次调用模型。

校验按岗位隔离，一个引文错误不重复调用整批成功项；重试明确要求复制原始标题作为引证。可选复核阶段使用紧凑父子路径，处理未分类和与精确三级名称不一致的项，模型仍结合正文判断，不直接用标题匹配覆盖职责。两阶段共享总调用预算；真正缺少职能信息的岗位单独输出待核验清单。

不改变岗位职责、学历、地址，不将分类补全等同于所有导入字段通过。配置不含密钥，环境变量读取密钥，不提交原始岗位数据与运行产物。

## 验收与测试

- JS 数据解析拒绝可执行表达式；配置与源文件所有父子路径一致，模板枚举一致。
- 非法路径、跨记录引证、缺失/重复 ID、截断响应不会写入有效分类；缓存变更失效，预算耗尽明确报告。
- 二十企业岗位表逐行分类校验；未分类数量及原因明确；原始时间与采集覆盖不变，程序输出 Excel 与增强快照一致。
- uv / Ruff / ty / pytest 通过，README 给出分类、缓存恢复和离线重导出命令。

本分支从已验收的 `feat/twenty-company-adapters` 创建，延续尚未合并 main 的正式实现，不从只含早期文档的 main 重新开发。
