# SPEC-012 Hotjob 公开校招租户

状态：六个 pb 租户已实现并真实验收，2026-10-12；移动入口等变体继续待适配。

## 目标与非目标

逐租户接入已填写的 Hotjob `pb/school.html` 校招入口，穷尽公开的 `recruitType=1` 岗位目录并核对每个岗位详情。复用平台协议，但每个租户分别探测、测试和真实验收后才启用绑定。不处理 `mc/position/campus` 移动版、登录投递、站点维护或明确为空的目录；这些入口另行记录障碍，不伪装为同一接口。

## 输入与输出

- 输入为来源清单中具体的 `SU...` 租户入口。观察页面 `listPosition` 的 URL 和表单，必须是 `isFrompb=true&recruitType=1`、第一页、没有未知筛选。按原分页大小逐页请求，`dataCount` 为总数、`totalPage` 为终点，`postId` 为唯一键。
- 详情由 `listPositionDetail` 的 `postId` 和 `recruitType=1` 获取，验证租户、岗位 ID 与类别。`workContent` 为职责、`serviceCondition` 为要求；只有明显的「【任职资格】/【任职要求】」标题才从合并正文拆分。缺要求留空并报字段警告。学历、单位、地点、类别与截止日期取详情，缺项才回退列表。
- `published` 优先用 `publishFirstDate` 首次发布时间；仅缺失时回退 `publishDate` 并保留字段路径。页面显示的“更新日期”不能覆盖首次发布时间。`source_url` 指向公开详情页，不自动调用投递接口。
- 从同租户公开的 `listSearchTerm.data.provinceList` 建立不歧义的单城市省/市路径，并将树响应附为字段证据；多城市、同名歧义或树外城市仍原样保存并进入待补全报告。
- 结果进入原有来源报告、JSON 快照、十三列严格表和信息汇总表。

## 失败行为

入口无法打开、租户或表单不匹配、业务响应失败、页码/总数变化、重复岗位、详情 ID 不符、超时及请求预算耗尽时记录问题，来源覆盖不为 complete；保留已成功岗位。零岗位需要单独确认真实零目录，不能因空白页或接口空响应自动启用绑定。个别岗位没有任职要求时保存其他真实字段和字段警告，不虚构要求。

## 可验证验收条件

1. 回放覆盖首/次/末页、详情关联、重复、空目录、缺字段，以及表单编码与缓存隔离；Ruff、ty、pytest 通过。
2. 每个启用的 `SU...` 租户均有真实运行，`expected == unique`、末页已到、`details + skipped_expired + skipped_window + reused_details == unique`、无覆盖问题，并记录时刻与岗位数。
3. 未证实的移动入口、维护页和空目录继续 pending，验收文档列出阻碍。采集快照保留供离线导出，不为生成表格重复抓取。
