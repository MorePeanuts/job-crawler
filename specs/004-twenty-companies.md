# SPEC-004 二十家企业接入与开发结果汇总

状态：开发中。

## 目标

在已有四家企业基础上，从用户名录新增十六家经过真实验收的企业。优先复用招聘平台，但逐租户验证入口、校招类型、分页、详情和完整性；企业绑定数量不等同于平台实现数量。开发期间成功采集的数据立即保存，最终由程序合并为二十家企业岗位表，不要求用户重新采集。

## 输入与范围

名录、显式企业绑定、原有模板和可配置分类树。选择过程以实际可访问的公开校招目录为准，记录被调查但未接入的入口及原因。不自动投递、登录或破解验证码；不将未接入企业计入二十家。

## 结果保留与汇总

- 每个企业保留独立原始采集目录、证据、覆盖报告和采集时间。沿用已有四站当日验收结果时明确其原始时刻，不声称重新采集。
- 新增离线合并命令，读取完整运行产物；按来源选择一个明确版本，不拼接不同轮次同一来源，不让新失败覆盖旧成功。重复来源默认拒绝，由调用者明确指定文件。
- 汇总在指定筛选时刻再次排除已截止岗位，但不将历史快照当作当前仍在线的验证。清楚保留每来源原始采集时间和覆盖状态。
- `jobs.xlsx` 继续严格导入校验；新增 `岗位信息汇总.xlsx` 按模板十一字段展示已采集且未明确过期的岗位，缺失分类等字段留空，不伪造。此表明确为待补全信息表，不宣称整体可直接导入。核验原因与采集覆盖单独保存。
- 合并结果必须覆盖二十个企业的报告，零条企业保留真实过滤原因，不制造占位岗位。JSON 保留完整正文，Excel 超长内容要有明确报告，不静默截断。

## 验收

逐企业记录平台、入口、校招范围、计数与结束条件，至少一条真实字段回放；公共平台测试验证分页、详情身份、过滤条件及部分失败。合并测试验证重复来源拒绝、原始时间保留、失效日期筛选、失败不掩盖和表格行数一致。执行 uv、Ruff、ty、pytest，更新 README 与本轮验收记录并分阶段提交。

## 已观察的平台契约

北森新版：`/api/Jobad/GetJobAdPageList`，请求 `Category=["2"]` 为实际校招页面观察值，`PageIndex=0` 开始，`Count` 为总数，`Data` 为岗位。保留站点实际筛选参数，不跨租户复用负载。列表包含 Duty/Require，详情日期等字段需对照详情确认。`0001-01-01` 为 .NET 未设置日期哨兵，不当作真实截止日期。

部分北森页面正常加载前被 Crawl4AI 的 `Structural: minimal_text` 空壳启发式提前判为失败。仅当适配器声明的业务端点在有限等待内返回成功 JSON 且目标地址匹配时可恢复；验证码或真正 403 不放行。成功后仍核验 Category、业务 Code、分页总数和详情。
