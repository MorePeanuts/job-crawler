# SPEC-034 岗位正文章节拆分与历史表修复

状态：已实现并完成昨日证据离线回放及工作簿核对，见 [验收记录](../docs/description-headings-acceptance.md)。未执行今日网站重采。

## 目标与非目标

修复合并正文按标题字串切分后残留 `【`、`】` 的问题，去除职责和要求字段中的冗余章节标题（包括 `【岗位职责】`）。排查并统一智联、前程无忧、Moka、Hotjob、哔哩哔哩的同类拆分逻辑，以及独立字段开头的同义标题。

不删除正文中有实际意义的括号或“岗位职责/任职要求”词语，不重新推断分类、学历、日期、地点，不重新抓取网站、调用模型或改变昨日岗位集合。

## 输入输出

- 在线解析输入是源站完整正文或独立职责/要求字段；输出为去除明确章节标题后的正文，保留正文、段落顺序和原始证据。
- 标题必须有明确的章节边界：成对括号、独立行或行首标题加标点；支持编号、标题跨 HTML 文本段、标题与内容同一行、职责/要求顺序互换。正文中一般词语不能触发拆分。
- 历史修复输入为 `outputs/today-collected-20261012-combined/` 的原始证据、快照和工作簿；另存修复版及逐岗位/单元格审计，不覆盖昨日原件。
- 历史工作簿仅允许职责、要求两列的正文变化。行数、顺序、其他列、工作表、样式、验证规则与链接保持不变；保留原采集时刻，不冒充新采集。

## 失败行为

- 未识别到标题时保持适配器既有的无标题回退，不猜测职责/要求的归属。
- 独立字段只剥离行首明确章节标题（含简介后的标题及源站写错的职责/要求标签），不移动结构化字段的内容；句子中的标题引用保留。
- 历史记录关联不唯一、证据与岗位 ID 不符、文件缺失、正文有无法解释的变化或工作簿其他字段改变时停止交付并报告；不凭残留括号任意删除正文。
