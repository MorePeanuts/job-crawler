# SPEC-003 浏览器入口就绪判定回归修复

状态：已实现并完成真实复验（2026-10-10）。起因：此前真实通过的中石油、阿里在正式版验收被报告为阻塞。

## 已确认事实

历史成功证据中，中石油入口 HTTP 状态就是 412，但浏览器最终显示招聘列表，listN 返回 HTTP 200。正式版新增 HTTP >= 400 立即拒绝，导致正常页面被提前中断。同环境重新运行原验证版已复现 412 + 正常岗位响应。因此不能将该次失败归为站点拒绝访问。

阿里在同环境运行原验证版也发生 60 秒 DOMContentLoaded 超时，无岗位接口响应。网络诊断显示招聘主程序 index.js（7,319,015 字节）一直处于下载中；独立下载 90 秒仅收到 2,686,114 字节。将正式程序页面等待上限调至 180 秒后，已收到列表与批次接口并进入完整分页。因此本次证据指向主资源加载缓慢，不能归因于岗位接口失效。

## 修复契约

- 平台适配器声明每次导航必须观察到的业务接口；不使用任意 XHR、统计请求或页面标题作为就绪证明。
- 导航正常时仍校验 HTTP 状态。对于已知的入口 HTTP 412，只在当前导航期间、当前页面同源且已观察到所声明接口的成功 JSON 响应时允许继续。真正的 401/403、无业务数据的 412 或其他 HTTP 错误继续失败。
- 如果仅为导航等待超时，保留当前浏览器页和本轮网络观察。只有页面地址属于本次目标、声明的业务接口均返回成功 JSON 时，才允许继续进入适配器字段与覆盖检查。不能靠旧响应、别的来源、无效 JSON 或非业务响应放行。
- 保留原始 HTTP 状态、导航警告、当前 URL、页面快照和就绪依据。导航降级不等于任务 complete；岗位结构、计数、身份、分页和子范围照常验证。
- 接口请求自身的 401/403/412 不因入口恢复逻辑而放行。无需改变浏览器身份、绕过登录或验证码。
- 页面导航使用独立 `crawl.navigation_timeout`，默认 180 秒；API 仍使用 `crawl.timeout`，默认 60 秒。两者均为正数，保留有限重试与单来源预算，不能无限等待。缺少新配置的旧 TOML 使用默认值。

## 验收

1. 412 + 本轮有效业务响应可继续；412 无业务响应、业务响应非 JSON、真正的 403 仍失败。
2. 导航超时 + 本轮所需业务响应可继续；未就绪、旧响应或跳转其他域名不能继续。
3. 所有恢复都有导航证据；恢复不改变计数、模板校验和任务状态规则。
4. 原有测试保持通过，新增入口恢复回归测试，并重新跑中石油/阿里真实全范围采集。
5. 更新验收记录，区分迁移问题、导航等待问题、真正站点不可达，纠正之前证据不足的归因。

结果：Ruff、ty、76 项测试通过。中石油完整获取 132 篇公告、1,190 个岗位；阿里在正式导航 180 秒/API 60 秒配置下完整获取 469 个岗位，阿里星 160 个岗位为子集。两站 coverage=complete；导入字段缺失导致整体 partial，原因与采集覆盖分开报告。命令、证据位置和当轮限制见 `docs/acceptance.md`。
