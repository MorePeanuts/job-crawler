状态：进行中；截至 2026-10-13 已完整验收 24/50 个来源，尚未满足五十家全覆盖目标。

## 后续四十二家复查（2026-10-13）

目标是逐一复核上轮未完成来源的原入口、当前官方入口和实际岗位目录；优先修复已存在的平台契约或过期入口，并实采可完成的来源。输入仍为下列 50 个来源 ID，已完成的 8 家不得重复计入新增家数。来源 URL 变更须有同一企业、同一招聘范围的公开证据；不得仅根据年份猜测新链接。

输出须包含逐来源障碍与修复状态、可复核的探测/采集证据、ready 绑定和程序汇总。无法打开、需登录、无目录、跨法人范围不清或只有旧活动的来源保持 pending；明确零岗位也要同时验证门户类别、无筛选请求、总数与终止条件。任何新增 ready 来源应有真实运行的 `coverage=complete` 和岗位计数；重放测试不能替代实采。

验收以本文件下方的全量验收条件为准，并补充：排查表必须覆盖剩余 42 个 ID，清楚区分「可以修复且已验证」「仍需实现」「源站/链接阻塞」；变更公共平台适配器时回归既有租户测试，入口更新后记录旧/新 URL 和依据。局部或受阻结果保留原始快照，不汇入完整岗位表。

公开岗位正文可能超过 Excel 单元格的 32,767 字符上限，或包含 Excel 不接受的控制字符。严格导入表继续将该记录放入待补全；信息汇总表保留该岗位行，用明确的引用文字代替不兼容单元格，同时把完整字段写入同目录的 `excel-overflow.json`。报告记录引用字段数量，不截断原始 `jobs.json` 和 `review.json`，也不让单条异常记录中断整站交付。

首次验收完成 8 家，详情见 [第四批验收记录](../docs/adapter-batch4-acceptance.md)。2026-10-13 对剩余 42 家复查后又实采通过 16 家，逐来源修复和另外 26 家障碍见 [本轮复查](../docs/adapter-batch5-triage.md)。程序对 24 家完整来源的快照重新汇总，原始记录 9,809 条，有效信息行 6,645 条，其中 1,944 条通过严格导入约束、4,701 条保留待补全。5 家明确零条有效岗位。该状态是阶段结果，不代表 SPEC-033 已完成。

## 目标

从最新版来源清单中选出 50 家尚未接入的企业，优先复用已实现的招聘平台适配器，同时为必要的新协议开发独立适配器；逐一验证入口范围、分页/分支终止、岗位详情关联和企业归属，采集本轮公开展示且仍有效的全部校招岗位，并通过程序生成一份汇总 Excel。

## 非目标

不绕过登录、验证码、403 或站点访问限制；不把历史招聘批次、实习、社会招聘或其他法人岗位混入目标；不手工补录岗位，不将局部结果或零结果说成完整采集。

## 输出

- 版本化适配器、逐来源 ready/pending 状态和脱敏回放测试。
- 每个被接入来源本轮独立的原始快照、采集报告和完整性证据。
- 一份由 `job-crawler bundle` 从本轮采集快照生成的 13 列 `岗位信息汇总.xlsx`，另含企业采集情况；严格导入表与待补全报告留在同一输出目录。
- 验收记录说明 50 家目标中实际完整接入家数、岗位数、过滤数、字段待补全数及所有阻塞来源。不得以“尝试 50 家”替代完成情况。

## 失败行为

目录/详情数不匹配、重复页、总数变化、历史活动页、无可靠终止标志、跨法人范围不清或明示访问限制时，保留已采集证据并将该来源标记为 partial/blocked/pending。零岗位只有在校招目录明确返回总数为 0、列表为空且有有效结束状态时才可验收为 complete。切换到候选池中的其他来源前须更新本 spec 的 ID 清单与调研依据。源站无可靠发布时间或截止时间时留空，不用采集时刻代替。

## 验收

1. 每个 ready 来源都有匹配的 URL、租户、岗位范围和适配器版本；每个目录/单位/批次有终止依据；unique 列表 ID 与详情或经证明可复用的详情数相符。
2. 每个 ready 来源当日真实运行 `coverage=complete`，岗位按本轮公开在招状态过滤；全量运行报告保留部分失败和排除理由。
3. 最终 Excel 每个岗位只由程序生成，岗位明细与企业采集情况页的公司和岗位计数一致，13 列和日期格式符合模板。
4. 执行 `uv sync --locked`、Ruff 格式与检查、`ty check`、`pytest`；真实站点验收和离线测试分开记录。
5. 在功能分支分阶段提交并推送，创建 PR；不合并 `main`。
