# SPEC-101 2026-10-15 新增五十家招聘适配器及岗位汇总

状态：进行中。日期：2026-10-15。

## 目标

以本批开始时 `sites/bindings.toml` 中已绑定的 178 个企业 ID 为基线，从名录选择未接入企业，新增并真实验收 50 个不同企业的招聘站点适配器。采集公开展示且未截止的正式校园招聘岗位，程序化生成十三列岗位信息表和严格导入表，按 2026-10-15 批次发布。

## 非目标

既有 178 家、同一主体多个入口、零有效岗位、仅离线测试通过或目录覆盖不完整的来源不计入 50 家。不以昨天的快照冒充今天实采，不手工补岗位及缺失字段，不自动投递、登录或绕过访问限制。

## 输入与输出

输入为 `sites/sources.csv` 中未绑定的 322 家名录主体：73 家已有招聘 URL，249 家尚无 URL。用户未指定固定名单，可从名录中替换受阻、零岗位、主体不符或已过期的候选；无 URL 来源须先以公开官方依据确认入口与主体。适配器复用既有平台须逐租户验证，不能仅凭域名绑定。

逐来源保存入口、列表、详情、范围、计数和分页末端证据，输出独立完整快照、报告及待补全数据；仅在真实覆盖验收后更新正式绑定。最终使用通过验收的快照离线 `bundle`，执行只读交付审计，将两份工作簿发布至 `outputs/2026-10-15/`。每个来源真实采集时间单独保留。

## 失败行为

旧入口、认证或网络阻断、仅实习或社招、集团法人边界不明、分页重复、详情身份不符、源总数变化和预算耗尽时，保留已采记录、证据与错误，并将受影响范围标为 partial 或 blocked。明确穷尽的零岗位来源可记 complete，但不计入 50 家。失败来源不污染成功来源的快照；未知企业字段和岗位字段保持待补全。

## 验收条件

1. 最终与批次起点 178 家比对，50 个不同的新 `company_id` 均有完整范围、可复核结束依据及至少一条有效正式校招岗位。
2. 各来源列表、详情和跳过计数闭合；源岗位 ID 与单位/批次构成唯一身份；发布时间、截止时间及法人归属均有源证据。
3. 新协议或现有平台扩展有针对其实际风险的离线回放测试；真实站点验收记录逐家说明时刻、范围、数量、局限与证据。
4. `bundle` 后审计 50 家、信息表与严格导入表行数、13 列及日期格式；归档发布并保留快照和证据。
5. `uv sync --locked`、Ruff 格式和静态检查、ty、pytest 通过；规范、实现、验收分别提交，按本地分支流程合并。

## 需求与测试对应

平台级分页、身份、失败和日期行为由相应 `tests/test_*` 验证。批次企业去重、报告与工作簿结构由 `.agents/skills/add-recruitment-adapters/scripts/audit_delivery.py` 只读核验。实时范围与主体归属由本批逐来源验收证据核对；未达 50 家时本规范保持进行中并明确缺口。
