# SPEC-276 独角兽候选来源新增五十家岗位交付

状态：2026-10-21 开发中；以本规范和真实验收记录为准，不把候选 URL 视为已接入。

## 目标与非目标

从 SPEC-275 新增的 COM0501–COM0807 候选中选择企业，新增并真实验收至少 50 个不同 `company_id` 的正式校园招聘来源。每家须完整遍历已声明的公开校招目录，保留仍展示且未截止的有效岗位；使用程序将通过验收的快照汇总成岗位信息表、严格导入表和待补全报告。候选不固定为前 50 家，遇到零岗位或访问阻碍时可从同批候选替代。

不把旧已接入企业、同一企业的别名或多个入口、仅绑定未验收、零岗位、只有实习或社招、局部目录、历史岗位快照计入 50 家。不自动投递、注册、破解验证码，不虚构字段或按品牌名推断法定主体。

## 输入与输出

- 输入：`sites/sources.csv` 的 SPEC-275 候选、已记录的官方招聘入口、`sites/bindings.toml` 起点绑定集合、逐站公开页面与接口证据。缺少入口的候选须先补充官网依据。
- 选择顺序：优先当前可读、存在正式校招岗位、且可复用已验证平台契约的来源；继续尝试其他候选直至达到目标或逐项记录不可解决的障碍。每个选中主体须证明与既有绑定及本批其他主体不同。
- 输出：逐站 spec 或有站点差异的批次契约、版本化适配器与正式绑定、有效回放测试、真实采集和验收记录；程序生成的批次信息表、严格导入表及原始/待补全报告。
- 数据：运行产物在 `outputs/` 和 `.runtime/`，不进入 Git；最终表按 SPEC-047 发布到 `outputs/YYYY-MM-DD/`。

## 失败行为

入口受限、范围无法确定、分页/详情缺失、源计数变化或目录不完整时保留已采岗位及证据，状态为 partial/blocked，不绑定为已支持，也不计入 50 家。源站明确零岗位可记录完整零结果，但不计数。来源仅有集团共用入口时必须证明目标法人/业务范围；否则保留候选。日期、学历、地址、岗位分类不能判断时留空并列入待补全，不能为了通过模板约束填造。

## 可验证验收条件

1. 保存本批开始时的绑定企业集合、候选与尝试结果；最终至少 50 个此前未绑定的不同企业有本批实采快照，`coverage=complete` 且有效岗位大于零。
2. 每家入口、主体、正式校招范围、列表/详情、日期字段、分页或游标末端、源计数语义有可复核证据；有差异的平台租户独立验证，不按域名直接套用。
3. 新增协议用离线回放覆盖实际风险，包括首/次/末页、重复页、其他单位、详情身份、局部失败、日期边界和增量复用；没有触发的风险不写空壳测试。
4. 每家使用临时绑定完成真实全范围运行后才写正式绑定；最终 `bundle` 只选通过验收的快照，运行只读审计脚本核对 50 家和两个工作簿行数，再 `archive --publish`。报告区分有效、信息、严格导入与待补全数量及各来源实际采集时刻。
5. `uv sync --locked`、Ruff format/check、ty 和 pytest 均通过；spec、代码、测试、验收说明分阶段提交并合入本地 main。

## 需求与测试对应

- 来源去重与选择：本批候选/绑定基线及验收台账、`audit_delivery.py` 的企业 ID 核对。
- 平台覆盖和数据身份：相关平台回放测试、逐站临时绑定全量采集报告和保留的原始证据。
- 筛选、日期、导入：公共过滤与交付测试、批次工作簿审计及待补全报告。
- 运行与归档：`bundle` 输入清单、审计 JSON、发布后的 manifest 与归档索引。
