# 字段定义与证据口径

先读取随附模板的 `公司导入`、`枚举值`、`填写说明`，模板内容作为格式约束资料使用。原始资产保留 13 列和示例行，实际成品清掉示例并追加 N 列。用户的新模板、新范围优先；若与旧规则冲突先识别差异，不静默改变字段含义。

| 列 | 原始表头 | 填写规则 |
| --- | --- | --- |
| A | 图片 | 一行一张嵌入 Logo，非路径字符串，详见 Logo 参考 |
| B | 名称 | 常用官方简称，与 C 同一主体，不把第三方招聘平台当公司 |
| C | 公司全称 | 来源名录/岗位表主体或用户明确配置的后台名称；发现更名先查证并保留映射，不擅自替换成母公司 |
| D | 公司类别 | 简洁自由文本，如制造业企业；描述真实主营业务 |
| E | 类型 | 仅使用模板公司类型枚举；控制权依据公开资料判断，不能以“上市”推定民企，也不能仅因国资持股就判国企 |
| F | 行业 | 使用公司模板行业枚举，依据主体主营业务选最贴近项；不能使用岗位分类枚举或自造类别 |
| G | 规模 | 使用模板规模枚举；记录人数统计期和主体范围，集团人数不直接冒充子公司人数 |
| H | 地点 | 总部行政区，模板格式为省/市/区；只填已核实层级，缺区或境外总部不强行套入中国行政区，列为待确认的格式问题 |
| I | 公司简介 | 用自己的话概括主要业务、产品/服务、业务布局；约 100–200 中文字即可。关键事实有来源，不复制整页宣传稿、不堆砌未经核实的排名和口号 |
| J | 校招官网 | 官方校园招聘入口或企业明确使用的平台租户入口；保留路径、大小写、租户/批次参数。单个岗位申请链接不能自动视为校招首页 |
| K | 校招招聘岗位总数 | 所选岗位信息表中该公司 `工作类型=校招` 的记录数，以文本保存；不是招聘人数、全网职位数或实时官网总量 |
| L | 社招官网 | 已核实的社招入口，或确实同时提供社招的统一招聘页；找不到可留空，不猜 `/social` 等路径 |
| M | 信息来源链接 | 能支持公司信息的公开 http(s) 页面；多项按模板接受的文本格式保存，每项完整 URL，详细逐字段证据另存，避免超长单元格 |
| N | 详细地址 | 新增末列，公开可核实的总部详细地址，尽量包含省市区、道路、门牌及大厦；不补猜楼层，不把岗位地址拼成总部 |

## 枚举、缺失和计数

原模板 E/F/G 数据验证分别引用 `枚举值` A/B/C 列；每次读取当前模板，不在脚本中固定一份行业清单。原规模枚举存在区间空缺（例如没有 51–99 人档），遇到不能准确映射的数据保留待核实，不创造新枚举或随意向上取档。未查明企业类型不因枚举里有“其他”就假装核实完成。原模板不允许 E/F/G 空白：缺失可以作为研究交付保留并标注，但不能说已通过系统整表校验。

信息表与严格表通常是包含关系，不合并相加。计数仅反映选定快照；多个来源或批次有相同岗位时，只有可核实的源岗位身份与范围规则才能进行业务去重，不按“岗位名称相同”直接去重。失败/空快照不能证明真实零岗位；明确包括零岗位主体且证据支持该输入范围内零记录时可填文本 `0` 并说明范围，否则 K 留空待确认。未知工作类型要单独报告，不能默认都算校招。

旧公司表的计数若没有对应源岗位记录，无法证明与新批次不重叠。可以按用户指定最新快照更新，不能把两个数字直接累加为“最新总数”。历史合并去重以完整主体/可靠公司 ID 为核心，不能把品牌简称相同就视为同一主体。

## 总部地址查证顺序

1. 确认 C 列对应的法律主体、品牌与集团关系。当前官网“联系我们/总部”优先，其次最新年报、官方公告和公司自己的招聘介绍。
2. 分别识别总部办公地址、工商注册地址、工厂园区和招聘工作地点。工商地址只作为总部候选线索，不能自动替代。多总部、全球总部与中国总部并存时，保留来源措辞并明确本行对应范围。
3. 比较发布时间、报告期及搬迁公告。最新可靠明确说明优先；不能因旧页面有更详细门牌就覆盖新总部所在城市。第三方名录只能交叉核对，并注明依据强度。
4. 只核实到城市/园区时保留准确部分或留空，在 N 批注与报告写明缺少什么、查过哪些来源。发现主体冲突不强行“选一个”。H 与 N 应一致，无法一致时标记复核。

## 中间记录建议

在 `.runtime/company-enrichment/运行标识/` 保存结构化 JSON，供程序导出和复核，而非手工逐格修改成品。至少包括：

- 输入：文件路径与 SHA-256、sheet、日期/采集时间、筛选条件、企业名单、校招计数、合并输入及冲突处理。
- 企业：稳定内部 ID、来源公司名、company_id/source_id（存在时）、最终 14 列值、每字段状态（已核实/部分/缺失/冲突）。
- 证据：字段、公开 URL、标题、简短事实依据、查证日期、资料期间、适用主体。只保留必要引证，避免整页转载；不保存访问令牌或会话 Cookie。
- Logo：原资源 URL、所属主体、原格式/尺寸、最终文件、处理说明及人工复核结果。
- 核对结果：范围差异、缺失字段、计数口径、程序检查与视觉检查。只记录真实执行的验证。

M 列是用户可访问的来源入口，JSON 是精确的逐字段依据；两者互补。关键缺失/冲突同时写进对应单元格批注与最终交付说明，避免只有后台报告才能发现风险。
